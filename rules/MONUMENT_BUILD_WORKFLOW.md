# Monument Build Workflow v49

## Purpose

This workflow generalizes the successful Taj Mahal project process for future large cultural, nostalgic, or landmark builds.

## Rule: recognition first, optimization second

Do not start by forcing a hard part cap if the build does not yet read correctly. First solve the recognizable macro identity. Then optimize.

```text
recognition → subsystem studies → screenshot validation → protected baseline → optimization
```

## Steps

1. **Define recognition-critical features**
   - Identify what makes the subject recognizable from medium distance.
   - Examples: dome/minarets for Taj, ring/gulch geometry for Halo, tower/platforms for Eiffel, gate/vehicle/paddocks for Jurassic Park.

2. **Build the macro silhouette**
   - Use scale and simple massing first.
   - Avoid micro-detail before the main read is solved.

3. **Study hard subsystems separately**
   - Dome, façade, tower, bridge, creature body, vehicle silhouette, skybridge, etc.
   - Keep study files separate from the main build.

4. **Promote only validated results**
   - A subsystem is not “solved” because the code is plausible.
   - It is solved when Blender/in-game screenshots confirm it.

5. **Freeze successful subsystems**
   - Do not rewrite minarets, bridge geometry, dome profile, or other working systems unless a specific defect justifies it.

6. **Optimize after recognition succeeds**
   - Replace hidden or low-value construction with larger parts.
   - Remove redundant rows.
   - Reduce equal-detail all-side work when the primary view and macro silhouette carry the build.
   - Preserve recognition-critical systems.

7. **Stop when the build meets the objective**
   - Do not chase perfection into regression.
   - If the build reads well and meets the part/performance target, document and finalize.

## Good optimization

- Replacing many hidden floor tiles with a few large floor panels.
- Replacing low-value dense socket pieces with one well-placed transition part.
- Simplifying rear/side detail after the front/macro read is solved.
- Keeping trim/banding that preserves architectural language.

## Bad optimization

- Removing silhouette-critical parts.
- Flattening a dome or creature body until it no longer reads.
- Deleting contextual elements that explain the subject.
- Changing many validated systems in one branch.

## Required output from every completed project

When a project is completed, create:

- final outcome summary
- what worked
- what failed
- validated part-use lessons
- non-generalizable project-specific observations
- failure modes to avoid
- final accepted version/baseline
