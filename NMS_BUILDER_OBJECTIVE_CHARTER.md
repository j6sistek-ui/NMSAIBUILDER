# NMS Builder Objective Charter

Status: active root-level objective definition.

## Purpose

The master documents exist to make AI sessions reliably generate, validate, and improve No Man's Sky Base Builder Python for the Blender plugin. The package is not only a part list. It is a transferable execution system for real NMS builds.

## Four linked objectives

1. **Improve advanced building capability.** Generate valid No Man's Sky Base Builder Python using real ObjectIDs, the Blender plugin, FBX-derived bounds, JSON-derived transform evidence, and validated placement recipes.

2. **Make the source package transferable.** A new AI/chat should be able to load the package, classify the request, apply the proper rule bundle, and produce the same disciplined workflow without relying on hidden memory from a prior conversation.

3. **Continuously expand build intelligence.** Convert user-provided JSON, screenshots, validation results, and build trials into reusable knowledge about part placement, connection techniques, styles, feature recipes, and output quality.

4. **Streamline data mapping.** Prefer compact algorithms, recipes, signatures, indices, and invariants over large context-heavy data dumps. Store enough source evidence to reproduce and adapt proven geometry without forcing every session to reread every prior example.

## Operating statement

When working on NMS builds, use this package as:

```text
request router
→ execution kernel
→ evidence lookup
→ recipe/control selection
→ invariant/parameter split
→ Python generation
→ validation gate
→ lesson promotion
```

The success metric is not whether the AI can describe the rule. The success metric is whether the generated build uses the rule correctly.

## What must be preserved from JSON

A working JSON example proves more than a literal object list. It can prove:

```text
which ObjectIDs work together
where they connect
how endpoint-to-endpoint systems close gaps
how rings, shells, curves, and domes maintain chord/contact
how stairs/ramp segments meet landings
how local coordinate frames scale and rotate as a unit
which orientation/scale behavior was actually saved by the game
```

Exact JSON recreation proves that the geometry can be transferred. Recipe extraction must then convert that control geometry into a reusable concept, not leave it trapped as one copied base.

## Non-goal

Do not turn every historical JSON into mandatory context for every prompt. Mine it into compact signatures and recipes, then load raw JSON only when the signature/recipe is insufficient, contradicted, or being validated.
